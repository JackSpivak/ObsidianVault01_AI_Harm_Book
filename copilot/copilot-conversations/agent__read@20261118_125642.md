**ai**: Your question makes sense. The answer is that there are two separate mechanisms, and they are often confused.

**Namespaces vs imports**
- **Namespaces** (`ho:`, `hov:`, `law:`) only name things. They are IRI prefixes, and they load nothing.
- **`owl:imports`** is what loads files. A file that imports another brings that file's contents into the same workspace.

**How the three layers would be tied together.** Each layer would be its own small ontology file with its own ontology IRI and version IRI. A fourth, tiny file imports the other three:
- `ho-core.ttl`: the OWL structure. It imports nothing from the other layers, so it works on its own.
- `ho-profiles.ttl`: the SHACL shapes. It imports the core.
- `ho-vocabulary.ttl`: the hubs and discipline schemes. It imports the core, so the IRIs it points to resolve.
- `ho-all.ttl`: it only says "import the three above".

**In Protégé you'd open `ho-all.ttl`.** The imports load automatically, and the Active Ontology tab lists the import closure. You don't load the three files by hand. If Protégé can't fetch an import from the web, it resolves it from local files, using the folder or a `catalog-v001.xml` file. That's from my general knowledge of Protégé, so check it against your version.

- **Core classes and properties:** in the Classes and properties tabs, with their short definition, altLabels, `designStatus` and source in the Annotations pane. This is where option 1 pays off: the class is readable on its own.
